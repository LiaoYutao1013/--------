# 模型部署总览

模型部署关注如何把训练好的模型变成稳定、快速、可维护的推理服务或边缘端应用。

## 部署流水线

```text
PyTorch / TensorFlow Model
  ↓
导出 ONNX
  ↓
图优化
  ↓
推理引擎 TensorRT / OpenVINO / ONNX Runtime
  ↓
量化 / 加速
  ↓
服务化或边缘部署
```

## ONNX

ONNX 是模型交换格式，用于把不同框架训练出的模型交给统一推理后端。

需要关注：
- opset 版本
- 动态 batch / 动态输入尺寸
- 算子是否支持
- 导出前后数值一致性

## TensorRT

TensorRT 是 NVIDIA GPU 上常用的高性能推理引擎。

优化方式：
- layer fusion
- kernel auto-tuning
- FP16
- INT8 quantization
- dynamic shape engine

## 量化

量化把 FP32 权重/激活压缩到 FP16、INT8 等格式。

| 类型 | 特点 |
|------|------|
| FP16 | 简单，精度损失小，GPU 友好 |
| PTQ | 训练后量化，流程快 |
| QAT | 量化感知训练，精度更稳 |

## 部署检查清单

- 输入预处理与训练时一致。
- 输出后处理与验证脚本一致。
- ONNX 输出与原模型误差在可接受范围。
- batch size 和动态尺寸已测试。
- 推理延迟、吞吐、显存占用已记录。
- 异常输入有处理逻辑。

## YOLO 部署重点

- letterbox 参数必须一致。
- NMS 可以在模型外做，也可以融合到部署图中。
- TensorRT 动态输入需要明确 profile。
- INT8 量化需要有代表性的校准数据。

## CMake 与跨平台部署

当视觉任务需要从 Python 原型走向跨平台 C++ 部署时，CMake 是最常见的构建层：

- 组织源文件、头文件和第三方依赖。
- 在 Windows / Linux / macOS 上统一构建流程。
- 对接 OpenCV、ONNX Runtime、TensorRT、CUDA、gflags、fmt 等库。
- 生成可安装、可打包、可交付的推理程序。
- 支持交叉编译和静态/动态链接切换。

重点关注：

- `target_*` 风格写法。
- `find_package` 和 `FetchContent`。
- 头文件路径、链接库、运行时库的区分。
- Debug / Release 配置差异。
- 安装规则 `install()` 与导出目标 `install(EXPORT ...)`。
- 跨平台时的路径、后缀和 DLL / so / dylib 管理。
