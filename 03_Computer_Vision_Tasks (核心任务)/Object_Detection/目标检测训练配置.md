# 目标检测训练配置

## 概述

目标检测训练同时优化分类、定位和目标存在性，训练难度高于普通分类。一个有效配置不仅包含优化器和学习率，还需要考虑输入尺寸、目标尺度、anchor 或 query 设计、数据增强、batch size、损失权重、NMS、评估指标和部署场景。

本文重点解释 `最优化理论` 中提到的学习率调度、批量大小和优化器选择在目标检测中的具体落地。

相关基础：[[../../01_Foundations (底层基石)/Math_for_CV (线性代数、概率论、最优化)/最优化|最优化理论]]

## 检测训练目标

典型检测模型输出：

```text
类别概率
目标存在性或前景概率
边界框位置
可选：关键点、mask、角度、属性
```

总损失常写作：

$$\mathcal{L} = \lambda_{cls}\mathcal{L}_{cls}
+ \lambda_{obj}\mathcal{L}_{obj}
+ \lambda_{box}\mathcal{L}_{box}$$

不同模型略有差异：

- YOLO：分类、objectness、bbox regression。
- Faster R-CNN：RPN 分类与回归、ROI 分类与回归。
- RetinaNet：Focal Loss + bbox regression。
- DETR：Hungarian matching + 分类 + L1 + GIoU。

相关：[[./YOLO_Loss_Functions|YOLO 损失函数]]

## 数据与标签检查

### 标签格式

常见 bbox 格式：

| 格式 | 含义 | 典型场景 |
|------|------|----------|
| `xyxy` | 左上角和右下角 | torchvision、检测后处理 |
| `xywh` | 左上角宽高 | COCO 标注 |
| `cxcywh` | 中心点宽高 | YOLO、DETR |

常见单位：

- 像素坐标。
- 归一化到 `[0, 1]` 的坐标。
- 特征图尺度坐标。

错误格式会导致训练 loss 看似下降但 mAP 为 0。训练前应可视化至少 50 张增强前后的图像和标签。

### 标签质量

检测标签应检查：

- bbox 是否越界。
- 宽高是否为 0 或负数。
- 类别 id 是否从 0 开始，是否连续。
- 目标是否漏标。
- 同一目标是否重复框。
- 小目标是否标注一致。
- 遮挡目标是否按任务规则标注。

漏标在检测任务中特别危险，因为模型会把真实目标当成背景学习。

### 数据统计

建议统计：

```text
每类图片数
每类实例数
bbox 宽高分布
bbox 面积分布
长宽比分布
每张图目标数量
小/中/大目标比例
图片分辨率分布
场景和光照分布
```

这些统计决定输入尺寸、anchor、增强和采样策略。

## 输入尺寸

### 尺寸对检测的影响

输入尺寸直接影响：

- 小目标可见像素。
- 特征图分辨率。
- 显存占用。
- 推理速度。
- batch size。

如果模型最大 stride 为 32，输入 640 时最深层特征图大小约为 20x20。一个 8x8 像素的小目标经过多次下采样后可能只剩极少信息。

### 常见设置

| 场景 | 输入尺寸建议 |
|------|--------------|
| 通用 YOLO 基线 | 640x640 |
| 小目标较多 | 960、1024、1280 |
| 实时部署 | 416、512、640 |
| 高精度离线检测 | 1024 以上或滑窗 |
| 遥感/工业大图 | tile 切片 + 高分辨率训练 |

### Letterbox

YOLO 常用 letterbox：

```text
原图等比例缩放
短边填充到目标尺寸
保持长宽比不变
```

优点：

- 不扭曲目标形状。
- 训练和推理尺寸固定。

注意：

- bbox 坐标需要考虑缩放比例和 padding。
- 评估和可视化时需要将坐标映射回原图。
- 填充颜色长期固定可能引入边界模式。

### 多尺度训练

多尺度训练随机改变输入尺寸：

```text
每隔若干 iteration 从 {512, 544, 576, ..., 768} 中采样一个尺寸
```

作用：

- 提高尺度鲁棒性。
- 适配不同推理尺寸。
- 降低对固定输入尺度的过拟合。

风险：

- 显存波动。
- batch size 可能受最大尺寸限制。
- 小目标任务中最小训练尺寸不能过低。

## Batch Size

### Batch Size 的作用

batch size 影响：

- 梯度噪声。
- BatchNorm 统计。
- 学习率选择。
- 训练吞吐。
- 显存占用。

检测模型每张图目标数量不同，所以即使图片 batch size 固定，正负样本数量也可能大幅波动。

### 有效 Batch Size

多卡和梯度累积时：

```text
effective_batch = batch_per_gpu * num_gpus * accumulation_steps
```

学习率应按有效 batch size 调整，而不是只看单卡 batch。

### 线性缩放

当 batch size 增加 $k$ 倍时，可尝试：

$$lr' = k \cdot lr$$

例如：

```text
batch 16, lr 0.01
batch 64, lr 0.04
```

检测中建议配合 warmup，并观察前几个 epoch 是否发散。

### 小 Batch 问题

检测任务常因高分辨率导致 batch 很小。问题包括：

- BatchNorm 统计不稳定。
- 梯度噪声大。
- loss 曲线波动。

解决方法：

- 冻结 BatchNorm。
- 使用 SyncBatchNorm。
- 使用 GroupNorm。
- 使用梯度累积。
- 降低学习率。
- 使用 AdamW 等自适应优化器。

## 优化器选择

### YOLO 系列

常见选择：

- SGD + Momentum：经典、泛化好。
- AdamW：更容易快速收敛，调参成本低。

SGD 起点：

```text
optimizer: SGD
lr: 0.01 for batch 64 as rough reference
momentum: 0.937 or 0.9
weight_decay: 5e-4
scheduler: warmup + cosine
```

AdamW 起点：

```text
optimizer: AdamW
lr: 1e-4 to 1e-3
betas: (0.9, 0.999)
weight_decay: 0.01 to 0.05
scheduler: warmup + cosine
```

### Two-stage 检测器

Faster R-CNN、Mask R-CNN 常见：

```text
optimizer: SGD + Momentum
lr: 0.02 for 16 images in classic Detectron-style configs
momentum: 0.9
weight_decay: 1e-4
scheduler: step decay or cosine
```

如果使用 Transformer backbone，也常切换到 AdamW。

### DETR 系列

DETR 常用 AdamW，并设置 backbone 更小学习率：

```text
optimizer: AdamW
backbone_lr: 1e-5
transformer_lr: 1e-4
weight_decay: 1e-4
gradient_clip: 0.1 or 1.0
```

原因：

- backbone 通常来自预训练。
- Transformer decoder 和检测 head 需要更大更新。
- 集合匹配训练对早期不稳定较敏感。

## 学习率调度

### Warmup

检测训练早期预测框通常很差，loss 可能很大。Warmup 有助于避免初期发散。

常见 warmup：

```text
warmup_epochs: 3 to 5
warmup_lr: 从 0 或较小值线性升到 base_lr
warmup_momentum: 从较低动量升到目标动量
```

YOLO 类训练中还常同时 warmup bias 学习率，使分类和 objectness head 更快进入合理范围。

### Cosine Decay

现代 YOLO 常用 warmup + cosine：

```text
前 3 到 5 epoch warmup
后续 cosine decay 到 lr_min
```

优点：

- 无需手工设置 step。
- 后期平滑降低学习率，有利于定位精修。
- 对不同训练长度较稳健。

### Step Decay

Two-stage 检测器经典配置常用 step decay：

```text
1x schedule: 12 epochs, decay at 8 and 11
2x schedule: 24 epochs, decay at 16 and 22
3x schedule: 36 epochs, decay at 27 and 33
```

适用于 COCO 风格基准，但迁移到新数据集时应根据验证曲线调整。

### 余弦重启

Cosine restart 会周期性增大学习率。检测中不如分类常见，使用时要注意：

- 重启可能导致定位指标短期下降。
- 适合长训练和多阶段探索。
- 最后阶段应保留低学习率收敛期。

## Weight Decay

### 检测中的权重衰减

Weight decay 对检测模型很重要，尤其是 backbone 和 head 参数量大时。

常见范围：

- SGD：`1e-4` 到 `5e-4`。
- AdamW：`0.01` 到 `0.05`。

不建议衰减：

- bias。
- BatchNorm/LayerNorm 参数。
- 有些实现中也不衰减位置编码。

### 欠拟合与过拟合判断

Weight decay 太大：

- train loss 降不下去。
- 小样本不能过拟合。
- 预测框置信度偏低。

Weight decay 太小：

- train 指标高，val 指标差。
- 类别置信度过高。
- 背景误检增加。

## 数据增强策略

### 基础增强

常用增强：

- 随机水平翻转。
- HSV 颜色扰动。
- 随机缩放。
- 随机平移。
- 随机仿射。
- 多尺度训练。

注意：

- 垂直翻转不适合所有场景，例如道路、行人、交通标志。
- 颜色增强要符合部署环境。
- 随机裁剪不能大量裁掉目标。

### Mosaic

Mosaic 将四张图拼接：

优点：

- 增加上下文多样性。
- 提高小目标训练频次。
- 单张训练图包含更多实例。

风险：

- 图像分布不真实。
- 边界处可能出现不自然目标。
- 后期继续强 Mosaic 可能影响定位精度。

建议：

```text
前中期使用 Mosaic
最后 10% 到 20% 训练关闭或降低 Mosaic
```

### Mixup

检测 Mixup 混合两张图及其目标框。

适用：

- 数据少。
- 类别不平衡。
- 背景变化大。

风险：

- 目标边界模糊。
- 对小目标和密集目标可能增加学习难度。

### Copy-Paste

Copy-Paste 将实例目标粘贴到其他背景图中。

适用：

- 实例分割。
- 缺陷检测。
- 小目标检测。
- 长尾类别增强。

关键：

- 粘贴位置要合理。
- 目标尺度要符合真实分布。
- 遮挡关系要自然。

相关：[[./Data_Augmentation_Strategies|数据增强策略]]

## Anchor 与匹配

### Anchor-based 检测

Anchor-based 模型需要将真实框匹配到预设 anchor。

影响因素：

- anchor 尺寸。
- anchor 长宽比。
- 特征层 stride。
- 正负样本匹配阈值。

如果数据集目标尺寸与默认 anchor 差异大，应重新聚类 anchor。

### Anchor 聚类

常用 k-means 按 bbox 宽高聚类，距离可用：

$$d(box, anchor) = 1 - IoU(box, anchor)$$

流程：

```text
收集所有 bbox 宽高
按输入尺寸归一化或映射
k-means 聚类得到 anchor
按面积分配到不同 stride 层
```

### Anchor-free 检测

Anchor-free 模型不依赖预设 anchor，但仍需设计：

- 正样本中心区域。
- 多尺度分配规则。
- 回归目标。
- center prior 或 quality score。

Anchor-free 不是免调参，只是减少 anchor 尺寸依赖。

## 损失权重

检测总损失各项量纲不同，需要权重平衡。

常见问题：

- box loss 太弱：框定位差，AP75 低。
- cls loss 太弱：类别混淆。
- obj loss 太弱：漏检。
- obj loss 太强：过度关注前景背景，定位提升慢。

调参建议：

1. 先使用成熟代码库默认权重。
2. 查看各 loss 分量数量级。
3. 根据指标拆解调整，例如 AP50 高但 AP75 低，优先关注定位。
4. 每次只调一个主权重。

## 训练阶段策略

### 冻结 Backbone

小数据微调时，可先冻结 backbone：

```text
stage 1: freeze backbone, train neck/head
stage 2: unfreeze all, lower lr fine-tune
```

优点：

- 防止预训练特征被破坏。
- 让新 head 先适应类别。
- 降低显存。

风险：

- 如果数据分布差异大，冻结太久会限制性能。

### 后期关闭强增强

许多 YOLO 训练会在最后若干 epoch 关闭 Mosaic、Mixup 等强增强。

目的：

- 让模型看到更真实的图像分布。
- 提升框定位和置信度校准。
- 减少不自然拼接带来的偏差。

### 高分辨率微调

流程：

```text
阶段 1: 中等分辨率训练，快速学习语义
阶段 2: 高分辨率微调，提升小目标和定位
```

注意：

- 高分辨率阶段 batch size 会降低。
- 学习率应相应减小。
- BN 可能需要冻结或同步。

## 小目标检测

小目标检测对训练配置特别敏感。

### 常见问题

- 输入缩放后目标像素太少。
- 深层特征 stride 太大。
- 正样本分配困难。
- 小目标被 Mosaic/Crop 进一步破坏。
- NMS 容易抑制密集小目标。

### 优化方向

- 增大输入分辨率。
- 使用更高分辨率特征层，例如 P2。
- 使用 tile 切片训练和推理。
- 调整 anchor 或匹配策略。
- 提高小目标采样比例。
- 使用 Copy-Paste 增强小目标。
- 调整 NMS 阈值和置信度阈值。

相关：[[./Small_Object_Detection_Optimization|小目标检测优化]]

## 类别不平衡与难样本

### 问题

检测中类别不平衡更复杂：

- 背景远多于前景。
- 常见类别远多于稀有类别。
- 易分类样本远多于难样本。
- 不同类别目标尺度不同。

### Focal Loss

Focal Loss 降低易样本权重：

$$FL(p_t) = -\alpha_t(1-p_t)^\gamma \log(p_t)$$

适合：

- one-stage 检测。
- 前景背景极不平衡。
- 难样本需要更高权重。

### 采样策略

常见方法：

- 类别均衡采样图片。
- oversample 含有少数类的图片。
- hard negative mining。
- 根据每类 AP 做 targeted data collection。

## 评估指标

### IoU 阈值

检测结果需要预测框与真实框 IoU 超过阈值才算匹配。

常见指标：

- AP50：IoU 0.50。
- AP75：IoU 0.75。
- mAP：多个 IoU 阈值平均。
- APs/APm/APl：小中大目标 AP。

解读：

- AP50 高、AP75 低：能找到目标但定位不准。
- APs 低：小目标能力差。
- 某类 AP 低：类别数据、标注或混淆问题。

### 置信度阈值

训练评估 mAP 时通常不固定高置信度阈值，而是扫过阈值计算 PR 曲线。部署时需要选择阈值：

- 阈值高：误检少，漏检多。
- 阈值低：召回高，误检多。

应根据业务成本选择，而不是只看默认值。

### NMS

NMS 删除高度重叠框：

```text
按置信度排序
保留最高分框
删除与其 IoU 超过阈值的其他框
重复
```

调参：

- NMS 阈值高：保留更多重叠框，适合密集目标。
- NMS 阈值低：抑制更强，误检少但可能漏检。
- 小目标密集场景可尝试 Soft-NMS、DIoU-NMS、WBF。

## 推理与训练一致性

训练和推理需要一致：

- 颜色空间。
- 图像归一化。
- resize/letterbox 逻辑。
- 类别顺序。
- bbox 坐标映射。
- NMS 配置。

常见部署错误：

- 训练 RGB，推理 BGR。
- 推理忘记除以 255。
- letterbox padding 反算错误。
- 类别 id 与名称错位。
- 导出 ONNX 后 sigmoid/softmax 重复或缺失。

## 配置模板

### 通用 YOLO 基线

```yaml
imgsz: 640
epochs: 100
batch: 16
optimizer: SGD
lr0: 0.01
momentum: 0.937
weight_decay: 0.0005
warmup_epochs: 3
scheduler: cosine
augment:
  hsv_h: 0.015
  hsv_s: 0.7
  hsv_v: 0.4
  degrees: 0.0
  translate: 0.1
  scale: 0.5
  fliplr: 0.5
  mosaic: 1.0
  mixup: 0.0
close_mosaic: 10
```

### 小目标优先配置

```yaml
imgsz: 1024
epochs: 150
batch: auto
optimizer: AdamW
lr0: 0.0005
weight_decay: 0.01
warmup_epochs: 5
scheduler: cosine
multi_scale: true
augment:
  mosaic: 1.0
  mixup: 0.05
  copy_paste: 0.2
close_mosaic: 20
notes:
  - use higher resolution feature if model supports P2
  - inspect APs and dense-scene NMS behavior
```

### DETR 风格配置

```yaml
optimizer: AdamW
lr: 0.0001
lr_backbone: 0.00001
weight_decay: 0.0001
batch_size: 16
epochs: 50
lr_scheduler: step_or_cosine
gradient_clip_norm: 0.1
loss:
  class_cost: 1
  bbox_cost: 5
  giou_cost: 2
```

## 实验排查

### mAP 为 0

优先检查：

1. 类别数是否正确。
2. 类别 id 是否从 0 开始。
3. bbox 格式和单位是否正确。
4. 评估脚本是否读取了正确验证集。
5. 预测坐标是否正确映射回原图。
6. 置信度阈值是否过高。
7. NMS 是否过强。

### AP50 高但 AP75 低

说明模型能找到目标，但定位不精确。

处理：

- 提高输入分辨率。
- 增加后期无强增强训练。
- 调整 box loss 权重。
- 使用更强 bbox loss。
- 检查标注框是否一致。

### 召回低

可能原因：

- 置信度阈值过高。
- 输入尺寸过小。
- 小目标太多。
- anchor 或匹配策略不合适。
- 数据增强裁掉目标。
- 类别漏标。

### 误检多

可能原因：

- 背景负样本不足。
- 标签漏标。
- 阈值过低。
- 类别相似度高。
- 训练集和部署背景不同。

处理：

- 加入 hard negative。
- 提高置信度阈值。
- 调整 NMS。
- 增强背景多样性。
- 清洗漏标数据。

## 与最优化理论的连接

| 检测配置 | 优化含义 |
|----------|----------|
| Warmup | 避免早期大梯度破坏检测头 |
| Cosine Decay | 后期小步精修定位 |
| Batch Size 缩放 | 控制梯度噪声与步长关系 |
| SGD + Momentum | 平滑 noisy detection gradients |
| AdamW | 自适应学习率并解耦权重衰减 |
| 关闭强增强 | 后期让目标函数更贴近真实分布 |
| 高分辨率微调 | 改变输入分布以提升小目标梯度信号 |
| Loss 权重 | 改变分类、目标性、定位的优化权衡 |
