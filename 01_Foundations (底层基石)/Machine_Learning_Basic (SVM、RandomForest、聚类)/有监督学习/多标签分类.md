# 多标签分类

多标签分类是有监督学习中“一个样本可以同时属于多个类别”的任务。每个样本的标签不是单个类别编号，而是一个由 0 和 1 组成的标签向量：

$$
y=[y_1,y_2,\dots,y_K],\quad y_k\in\{0,1\}
$$

其中 $y_k=1$ 表示第 $k$ 个标签存在，$y_k=0$ 表示不存在。

视觉任务中的例子：

- 一张街景图同时包含 `car`、`person`、`traffic light`。
- 一张工业缺陷图同时有 `scratch`、`stain`、`edge broken`。
- 一张医学图像同时标注多个病灶属性。
- 一张商品图同时具有 `red`、`round`、`metal` 等属性标签。

## 和多分类的区别

| 问题 | 标签是否互斥 | 输出形式 | 例子 |
|------|--------------|----------|------|
| 多分类 | 互斥 | 一个类别 | 猫/狗/鸟三选一 |
| 多标签分类 | 不互斥 | 多个二值标签 | 图中同时有人、车、交通灯 |

多分类通常使用 softmax，因为所有类别概率加起来为 1。多标签分类通常使用 sigmoid，因为每个标签都是独立的“是否存在”判断。

```text
多分类：
cat 0.80 + dog 0.15 + bird 0.05 = 1.00
最终只选一个类别

多标签分类：
person 0.92
car    0.81
light  0.63
tree   0.10
每个标签单独判断是否出现
```

## 标签表示

假设标签集合是：

```text
["person", "car", "traffic_light", "tree"]
```

一张图含有人、车和交通灯，不含树，则标签向量为：

```text
[1, 1, 1, 0]
```

一张图只含树，则标签向量为：

```text
[0, 0, 0, 1]
```

标签顺序必须固定。训练、验证、测试、推理阶段都要使用同一个标签列表，否则模型输出会被解释错。

## 建模方法

### Binary Relevance

Binary Relevance 把多标签任务拆成 $K$ 个二分类任务：

```text
是否有人？
是否有车？
是否有交通灯？
是否有树？
```

优点是简单、可并行、容易实现。缺点是没有显式建模标签之间的关系，例如 `traffic_light` 和 `car` 在街景中经常共同出现。

### Classifier Chains

Classifier Chains 按顺序训练多个分类器，后面的分类器可以使用前面标签的预测结果：

```text
x -> person
x + person -> car
x + person + car -> traffic_light
```

它能利用标签相关性，但标签顺序会影响结果，错误也可能沿链传播。

### Label Powerset

Label Powerset 把每一种标签组合当成一个类别。例如：

```text
[person, car] -> 类别 A
[person, car, traffic_light] -> 类别 B
[tree] -> 类别 C
```

它可以捕捉标签组合，但标签数量多时组合数爆炸，不适合大标签集合。

### 神经网络多标签分类

深度学习中常用一个共享特征提取器，再接 $K$ 个 sigmoid 输出：

```text
图像
  ↓
CNN / Transformer 特征
  ↓
K 个 sigmoid 输出
  ↓
每个标签一个概率
```

每个标签概率独立阈值化：

```text
p_k >= threshold_k -> 标签 k 存在
```

## 损失函数

多标签分类常用 Binary Cross Entropy：

$$
L=-\frac{1}{K}\sum_{k=1}^{K}\left[y_k\log(p_k)+(1-y_k)\log(1-p_k)\right]
$$

它等价于对每个标签分别计算二分类交叉熵，再求平均。

如果标签极不均衡，可以使用：

- 标签权重：让稀有标签的正样本损失更大。
- Focal Loss：降低大量容易负样本的影响。
- 重采样：增加稀有标签样本出现频率。

## 阈值策略

默认阈值常设为 0.5，但实际任务中不一定合理。

### 全局阈值

所有标签使用同一个阈值：

```text
threshold = 0.5
```

优点是简单。缺点是不同标签的频率、难度、代价可能差异很大。

### 每标签阈值

每个标签单独选择阈值：

```text
person: 0.60
car: 0.55
traffic_light: 0.35
tree: 0.70
```

稀有标签或更重视召回的标签可以使用较低阈值。阈值应在验证集上选择，不能在测试集上反复调。

### Top-K 输出

有些系统只希望返回概率最高的前几个标签，例如自动标注推荐。这时可以取 Top-K，但要注意 Top-K 不代表标签真的存在，只代表模型最有信心的候选。

## 评价指标

多标签分类不能只用普通 Accuracy，因为一个样本有多个标签，预测可能部分正确。

### Hamming Loss

Hamming Loss 统计所有标签位中预测错误的比例：

$$
HammingLoss=\frac{1}{nK}\sum_{i=1}^{n}\sum_{k=1}^{K}I(y_{ik}\ne \hat{y}_{ik})
$$

值越小越好。它关注每一个标签位是否预测正确。

### Subset Accuracy

Subset Accuracy 要求一个样本的所有标签都完全预测正确：

```text
真实：[1, 1, 0, 0]
预测：[1, 1, 0, 0] -> 正确
预测：[1, 0, 0, 0] -> 错误
```

它非常严格，标签数量多时通常较低。

### Micro / Macro F1

| 指标 | 计算方式 | 关注点 |
|------|----------|--------|
| Micro F1 | 汇总所有标签的 TP/FP/FN 后计算 | 高频标签影响更大 |
| Macro F1 | 每个标签先算 F1，再平均 | 稀有标签权重更高 |
| Weighted F1 | 按每个标签样本数加权平均 | 更接近总体分布 |

当稀有标签很重要时，Macro F1 和每标签 Recall 比 Micro F1 更有价值。

### mAP

mAP 常用于多标签图像分类和目标检测。它先对每个标签计算 AP，再对所有标签平均。

```text
AP(person)
AP(car)
AP(traffic_light)
...
mean -> mAP
```

mAP 不依赖固定阈值，更适合比较模型排序能力。

### Jaccard / IoU

把预测标签集合和真实标签集合看作两个集合：

$$
Jaccard=\frac{|Y\cap \hat{Y}|}{|Y\cup \hat{Y}|}
$$

它衡量预测标签集合和真实标签集合的重合程度。

## 示例代码：OneVsRest 多标签分类

```python
import numpy as np
from sklearn.datasets import make_multilabel_classification
from sklearn.model_selection import train_test_split
from sklearn.multiclass import OneVsRestClassifier
from sklearn.linear_model import LogisticRegression
from sklearn.metrics import classification_report, hamming_loss, jaccard_score

X, y = make_multilabel_classification(
    n_samples=800,
    n_features=20,
    n_classes=5,
    n_labels=2,
    allow_unlabeled=False,
    random_state=0,
)

X_train, X_test, y_train, y_test = train_test_split(
    X,
    y,
    test_size=0.25,
    random_state=0,
)

model = OneVsRestClassifier(
    LogisticRegression(max_iter=1000)
)

model.fit(X_train, y_train)
proba = model.predict_proba(X_test)

threshold = 0.5
pred = (proba >= threshold).astype(int)

print("hamming loss:", hamming_loss(y_test, pred))
print("jaccard samples:", jaccard_score(y_test, pred, average="samples"))
print(classification_report(y_test, pred, zero_division=0))
```

`OneVsRestClassifier` 本质上训练多个二分类器，每个标签一个。实际图像任务中，`X` 可以替换成 CNN embedding、HOG 特征、颜色纹理特征等。

## 示例代码：为每个标签单独调阈值

```python
import numpy as np
from sklearn.metrics import f1_score

def choose_thresholds(y_true, proba, candidates=None):
    if candidates is None:
        candidates = np.linspace(0.05, 0.95, 19)

    thresholds = []
    for label_idx in range(y_true.shape[1]):
        best_threshold = 0.5
        best_f1 = -1.0

        for threshold in candidates:
            pred = (proba[:, label_idx] >= threshold).astype(int)
            score = f1_score(y_true[:, label_idx], pred, zero_division=0)

            if score > best_f1:
                best_f1 = score
                best_threshold = threshold

        thresholds.append(best_threshold)

    return np.array(thresholds)

thresholds = choose_thresholds(y_test, proba)
pred = (proba >= thresholds).astype(int)
print("thresholds:", thresholds)
print(classification_report(y_test, pred, zero_division=0))
```

真实项目中，阈值应使用验证集选择。测试集只用于最后报告，不能反复用来挑阈值。

## 数据标注注意点

### 缺失标签不等于负标签

多标签数据中最容易出错的是把“没标”当成“不存在”。例如一张图确实有交通灯，但标注员漏标了。如果训练时把它当负样本，模型会收到错误监督。

需要区分：

```text
1：确定存在
0：确定不存在
unknown：未知或未标注
```

如果存在大量未知标签，训练和评估都要特殊处理。

### 标签粒度一致

标签集合要避免重叠定义。例如同时有 `vehicle` 和 `car` 时，一张车图是否两个都标？如果规则不清，模型会学习到混乱目标。

### 标签共现关系

多标签任务中标签不是独立出现的。街景中的 `car`、`road`、`traffic_light` 常共现；工业缺陷中的某些类型可能互斥。分析共现矩阵有助于发现标注问题和模型偏差。

## 错误分析

建议按标签逐个分析：

- 每个标签的正负样本数。
- 每个标签的 Precision、Recall、F1。
- 高频标签是否掩盖了稀有标签的问题。
- 哪些标签容易共同漏检。
- 哪些标签容易互相误报。
- 预测概率是否普遍偏低或偏高。
- 阈值变化对业务结果的影响。

## 常见风险

### 只看样本级准确率

Subset Accuracy 过于严格，Micro F1 又可能被高频标签主导。多标签任务应该同时报告样本级、标签级和整体指标。

### 阈值没有业务含义

0.5 只是默认值，不一定符合业务要求。比如安全检测中，某些危险标签应该优先保证 Recall；自动打标中，则可能更重视 Precision。

### 标签数量过多

标签数量很大时，负样本会远多于正样本，训练容易被负样本主导。需要考虑类别权重、采样策略、层级标签或候选标签召回策略。

### 多标签分类和目标检测混淆

多标签分类只判断“图里有没有某类对象”，不输出对象位置。如果任务需要知道每个对象在哪里，应使用目标检测或分割，而不是只做多标签分类。
