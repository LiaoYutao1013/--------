# 序列预测

序列预测是处理有顺序数据的有监督学习任务。样本不再是单个独立输入，而是一段按时间、空间或阅读顺序排列的序列：

$$
X=(x_1,x_2,\dots,x_T)
$$

模型可以预测一个整体标签、每个时间步的标签，或未来的序列。

在视觉任务中，常见例子包括：

- 视频动作识别：一段视频预测一个动作类别。
- 视频帧级标注：每一帧预测一个动作状态。
- OCR：图像中的字符按顺序输出。
- 目标跟踪：根据历史状态预测下一帧位置。
- 工业过程监控：根据连续帧特征预测异常是否即将发生。

## 序列任务类型

| 类型 | 输入 | 输出 | 视觉例子 |
|------|------|------|----------|
| 序列分类 | $x_{1:T}$ | 一个标签 $y$ | 视频动作识别 |
| 序列标注 | $x_{1:T}$ | 标签序列 $y_{1:T}$ | 每帧动作状态、逐字符 OCR |
| 序列到序列 | $x_{1:T}$ | 另一段序列 $y_{1:M}$ | OCR、图像字幕、视频描述 |
| 下一步预测 | $x_{1:T}$ | $x_{T+1}$ 或 $y_{T+1}$ | 跟踪位置预测、时间序列预测 |

其中 $T$ 是输入序列长度，$M$ 是输出序列长度。很多序列任务的难点在于：输入和输出长度不一定相同，标签也不一定能和每个输入位置严格对齐。

## 和普通分类/回归的区别

普通分类或回归常假设样本之间相互独立：

```text
image_1 -> label_1
image_2 -> label_2
image_3 -> label_3
```

序列预测则强调顺序和上下文：

```text
frame_1 -> frame_2 -> frame_3 -> ... -> frame_T
```

同一帧单独看可能无法判断动作，但结合前后帧就能识别。例如“拿起杯子”和“放下杯子”在单帧中可能很像，区别主要来自时间变化。

## 数据表示

### 固定长度窗口

把连续数据切成长度固定的小窗口：

```text
[frame_1, ..., frame_16] -> action
[frame_9, ..., frame_24] -> action
[frame_17, ..., frame_32] -> action
```

优点是容易批处理，适合传统机器学习和深度学习。缺点是窗口长度需要选择，太短可能缺上下文，太长可能引入噪声。

### 变长序列

真实视频、文本行、轨迹长度通常不同。深度学习中常用 padding 和 mask：

```text
真实序列：[x1, x2, x3]
补齐序列：[x1, x2, x3, PAD, PAD]
mask:     [1,  1,  1,  0,   0]
```

mask 用来告诉模型和损失函数哪些位置是真实数据，哪些只是补齐。

### 特征序列

传统视觉流程中，可以先对每帧提取特征，再对特征序列建模：

```text
视频帧
  ↓
每帧提取 HOG / 光流 / CNN embedding
  ↓
得到特征序列
  ↓
HMM / CRF / RNN / Transformer / 传统分类器
```

## 常见模型

| 模型 | 核心思想 | 适合场景 |
|------|----------|----------|
| 滑动窗口 + 传统分类器 | 把一个窗口拼成固定特征再分类 | 简单视频分类 baseline |
| HMM | 建模隐藏状态和观测序列 | 状态转移明显、数据较小 |
| CRF | 对标签序列做条件建模 | 序列标注、相邻标签约束 |
| RNN / LSTM / GRU | 递归处理时间序列 | 中等长度序列、动作识别 |
| 1D CNN / TCN | 用时间卷积提取局部模式 | 长序列、并行训练 |
| Transformer | 自注意力建模长距离依赖 | 大数据、长上下文、多模态任务 |
| CTC | 输入输出未严格对齐时训练序列 | OCR、语音识别 |

## 损失函数

### 序列分类损失

如果整段序列只有一个标签，可以先把序列编码成一个向量，再使用普通分类交叉熵：

```text
x_1, x_2, ..., x_T
  ↓
sequence encoder
  ↓
sequence representation
  ↓
softmax
  ↓
cross entropy
```

### 逐时间步交叉熵

如果每个时间步都有标签：

$$
L=-\frac{1}{T}\sum_{t=1}^{T}\log P(y_t|x_{1:T})
$$

有 padding 时，只对 mask 为 1 的真实位置计算损失。

### CTC Loss

OCR 常遇到输入位置和输出字符无法严格对齐的问题。例如一张文字图像被 CNN 切成 50 个时间步，但最终只有 8 个字符。CTC 允许模型在不知道逐字符边界的情况下训练。

CTC 的典型流程：

```text
图像特征序列
  ↓
每个时间步预测字符或 blank
  ↓
合并重复字符并去掉 blank
  ↓
得到最终文本
```

### 回归序列损失

如果预测的是连续值序列，例如目标位置轨迹，可以使用 MSE、MAE、Huber Loss：

$$
L=\frac{1}{T}\sum_{t=1}^{T}(y_t-\hat{y}_t)^2
$$

## 评价指标

| 任务 | 常用指标 | 说明 |
|------|----------|------|
| 序列分类 | Accuracy、F1 | 整段序列预测是否正确 |
| 帧级标注 | Per-frame Accuracy、Macro F1 | 每个时间步是否正确 |
| OCR | Edit Distance、CER、WER、Exact Match | 输出字符串和真实字符串差异 |
| 跟踪/轨迹预测 | MAE、RMSE、ADE、FDE | 坐标误差或轨迹误差 |
| 动作检测 | mAP、IoU over time | 时间片段是否定位正确 |

### Edit Distance

编辑距离统计把预测序列变成真实序列所需的插入、删除、替换次数。OCR 中常用字符错误率 CER：

$$
CER=\frac{EditDistance(\hat{Y},Y)}{|Y|}
$$

如果真实文本是 `VISION`，预测是 `VIS1ON`，编辑距离为 1，CER 为 $1/6$。

### ADE 和 FDE

轨迹预测中常用：

- ADE：所有时间步平均位移误差。
- FDE：最后一个时间步的位移误差。

FDE 对最终位置特别敏感，适合关注目标最终落点的任务。

## 数据划分

序列任务最容易发生数据泄漏。不能把同一个视频的相邻帧随机分到训练集和测试集，因为相邻帧高度相似。

推荐按更高层级划分：

```text
按视频划分
按病人划分
按生产批次划分
按采集日期划分
按设备或场景划分
```

如果任务是时间预测，还要注意不能用未来数据预测过去。时间序列通常按时间顺序切分，而不是随机切分。

## 示例代码：滑动窗口序列分类 baseline

下面示例把连续观测切成固定长度窗口，再用随机森林预测窗口末尾的状态。这个方法不是最强模型，但很适合理解序列数据如何变成监督学习样本。

```python
import numpy as np
from sklearn.ensemble import RandomForestClassifier
from sklearn.metrics import classification_report
from sklearn.model_selection import train_test_split

rng = np.random.default_rng(0)

n_steps = 1200
n_features = 3
X_series = rng.normal(size=(n_steps, n_features))

# 构造一个带时间依赖的二分类标签：
# 当前状态不仅取决于当前特征，也取决于前几个时间步。
signal = (
    0.8 * X_series[:, 0]
    + 0.5 * np.roll(X_series[:, 1], 1)
    - 0.4 * np.roll(X_series[:, 2], 2)
)
y_series = (signal > 0.6).astype(int)

window = 8
X_windows = []
y_windows = []

for end in range(window, n_steps):
    start = end - window
    X_windows.append(X_series[start:end].ravel())
    y_windows.append(y_series[end])

X_windows = np.asarray(X_windows)
y_windows = np.asarray(y_windows)

X_train, X_test, y_train, y_test = train_test_split(
    X_windows,
    y_windows,
    test_size=0.25,
    shuffle=False,
)

model = RandomForestClassifier(
    n_estimators=200,
    max_depth=8,
    random_state=0,
)

model.fit(X_train, y_train)
pred = model.predict(X_test)

print(classification_report(y_test, pred))
```

这里使用 `shuffle=False`，因为示例模拟的是时间序列预测。真实任务中是否能随机切分，取决于部署时是否会遇到同一序列的相邻片段。

## 示例：OCR 的序列思想

OCR 不是简单的图像分类。一张文本图像可能包含多个字符，输出长度也不固定：

```text
输入：包含 "A12B7" 的图像
输出：["A", "1", "2", "B", "7"]
```

典型 OCR 模型会把图像变成从左到右的特征序列：

```text
文字图像
  ↓
CNN 提取二维特征
  ↓
沿宽度方向展开为序列
  ↓
RNN / Transformer 建模上下文
  ↓
CTC 或 attention decoder 输出字符序列
```

相比把整张图分类成某个固定类别，序列建模能处理不同长度的文本。

## 示例：视频动作识别

视频动作识别通常不是单帧分类，而是聚合多个帧的信息：

```text
采样 16 或 32 帧
  ↓
提取每帧或每段特征
  ↓
时间建模
  ↓
输出动作类别
```

如果动作发生在视频的一小段时间内，还需要动作定位：

```text
视频 -> 动作类别 + 起止时间
```

这时指标会同时考虑分类是否正确和时间区间是否重叠。

## 常见风险

### 相邻帧泄漏

同一视频相邻帧非常相似。如果随机划分帧，模型可能在测试集中看到几乎一样的画面，导致指标虚高。

### 标签对齐错误

帧级标注、OCR、轨迹任务都依赖对齐。如果标签时间戳、字符顺序或坐标系统有偏移，模型会学习到错误监督。

### 序列长度选择不合理

窗口太短会丢失上下文，窗口太长会增加噪声和计算量。应根据动作持续时间、采样率、目标变化速度选择长度。

### 类别持续时间不均衡

视频中“背景”或“正常状态”可能占绝大多数帧，异常动作只有很短时间。此时逐帧 Accuracy 可能很高但模型完全漏掉关键事件，应重点看关键类别 Recall、事件级指标或 mAP。

### 训练和推理方式不一致

训练时如果使用完整序列，部署时却只能实时看到过去帧，模型可能依赖未来信息。在线预测任务必须保证训练输入和推理输入的信息范围一致。

## 实践建议

- 先用滑动窗口 + 传统分类器建立 baseline。
- 数据划分优先按视频、对象、病人或时间段进行。
- 保存每个序列的来源 ID，方便排查泄漏。
- 对变长序列使用 padding + mask。
- 对 OCR 等未对齐任务优先考虑 CTC 或 attention decoder。
- 指标要匹配任务：整段分类看 Accuracy/F1，逐帧标注看 frame-level F1，文本序列看 CER/WER，轨迹预测看 ADE/FDE。
